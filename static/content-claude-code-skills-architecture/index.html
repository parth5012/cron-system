Option 1: The Autocomplete Trap Standalone Post
Main Tweet 264 / 280 chars
Most devs use terminal coding agents like glorified autocomplete. You give it a prompt, get 200 lines of unverified code, and spend an hour fixing edge cases. Without deterministic skills in your harness, you are using maybe 10% of what the agent can actually do.
Option 2: The TDD Confirmation Bias Trap Post + 1 Reply
Main Tweet 224 / 280 chars
The biggest flaw with AI coding agents: if you let them write code and tests together, they write tests designed to pass against their own bugs. It creates an illusion of correctness while breaking edge cases in production.
Reply 1 248 / 280 chars
The fix is enforcing a strict TDD skill: 1. Agent writes the failing test first (RED) 2. Implements minimal code to pass (GREEN) 3. Refactors with an 80%+ coverage check Don't let the model grade its own homework without deterministic guardrails.
Option 3: Architecture Before Code Post + 1 Reply
Main Tweet 240 / 280 chars
Junior devs rush to write code. Senior devs read architecture docs first. Coding agents do the same: without constraints, they start editing files without knowing your project invariants, creating tech debt you only notice two weeks later.
Reply 1 225 / 280 chars
We fixed this by adding a pre-execution interrogation skill. Before touching a file, the agent reads existing ADRs and domain models, then questions your architectural choices. It stops bad implementations before they start.
Option 4: Model vs Harness Standalone Post
Main Tweet 243 / 280 chars
Everyone obsesses over which frontier model ranks #1 on SWE-bench this week. In practice, the model is a commodity. The real difference between shipping clean software and drowning in AI slop is your local skill harness and verification loop.
Option 5: The Security PR Auditor Post + 1 Reply
Main Tweet 240 / 280 chars
Ran an automated security reviewer skill on an internal auth PR. It caught something the team missed: a CSRF bypass relying on gateway proxy assumptions that worked in production, but silently broke in staging because the proxy was absent.
Reply 1 246 / 280 chars
Standard linters catch syntax errors. A disciplined review skill inspects trust boundaries, unconstrained string types, and audit logging. Codifying your senior staff engineer's review checklist into a reusable skill pays for itself immediately.
